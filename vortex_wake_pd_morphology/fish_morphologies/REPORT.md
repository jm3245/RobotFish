# 不同关节数仿生鱼：20 秒正弦行波验收

## 现有环境与模型

读取了 `eel_swimming/assets/eel_pool_v4_scene.xml`、`eel_pool_v4_visuals.xml`、`scene_config.py` 和 `scripts/run_v4_trials.py`。原鱼为长约 1 m、朝 +X 的 20 段圆柱链；19 个竖直转轴铰链中有 5 个受扭矩电机控制。原循环以 0.001 s 积分、每 0.02 s 更新控制；场景采用 `density=1000 kg/m³`、`viscosity=0.001 Pa·s`、`gravity=0 0 0`、Euler、`wind=0 0 0`。鱼 geom 未设置 `fluidshape` 或 `fluidcoef`，因此使用 MuJoCo 默认 inertia-box 流体模型。V4 泳池几何均不碰撞，只作视觉参照。

生成器直接从现有场景复制 `compiler`、`option`、`visual`，从 V4 视觉 XML 复制泳池，不改变水参数。长度单位为 m，角度为 rad，力矩为 N·m。零重力环境中没有实际浮力项；鱼体密度默认与水相同，只表示接近中性浮力的材料设定，不能据此声称验证了浮力平衡。

## 鱼体与控制

每条鱼有一个自由根头部和 N 个串联节段，均用渐缩椭球体表示。尾段有竖直尾鳍；默认尾鳍投影面积 0.018 m²，高 0.18 m。所有关节绕 +Z 转动，范围 ±0.75 rad，刚度 0.01 N·m/rad，阻尼 0.015 N·m·s/rad；位置执行器 `kp=35`、`kv=0.6`、力矩上限 ±12 N·m。鱼体密度为 1000 kg/m³，体长 1 m。关节还使用 0.0005 kg·m² 等效驱动转子惯量以稳定短节段的伺服动力学。8 个中线 site 按从鼻端到尾端的弧长比例 `s=j/7` 放置；头部提供 `framequat` 和 `velocimeter`。

每个关节的目标角为 `A_i sin(2πft−2πφi/N)`，其中 `A_i=A_max[0.3+0.7i/(N−1)]`。开始 1 s 线性渐入，控制目标裁剪到关节范围。每种鱼扫描 5 个频率 × 3 个最大幅度 × 3 个相位滞后，共 45 组，每组 20 s。平均前进速度是全鱼 COM 沿初始 +X 的净位移除以 20 s；横漂也取 COM 净位移。净偏航为头部四元数解缠后的末初差；CSV 另记绝对偏航运动量，避免将周期摆头误当净转向。长期撞限位定义为超过 5% 的控制采样点中任一关节达到其角度范围的 98%。筛选时还要求横漂小于 0.25 倍体长、净偏航小于 45°。

## 调整与局限

第一轮完整扫描时，N=6、8 的短节段在位置伺服下频繁撞限位，横漂和偏航不合格。调参试跑分别检查了较高阻尼/较低增益及等效转子惯量；前者抑制了推进，后者让关节角稳定跟随正弦目标。统一加入 0.0005 kg·m² 等效转子惯量后，第二轮完整扫描五种形态全部达标。水参数、重力与积分步长始终未改。

这是 MuJoCo 内置近似流体力模型中的推进结果，不是 CFD 或真实水槽标定。水力在场景中全域生效，但视觉泳池只有 10 m 长且没有碰撞边界；最佳步态在 20 s 内可游过视觉边界。轨迹图仍画完整 20 s，GIF 用仿真前 6 s 的 MuJoCo 离屏渲染状态，以便看到鱼在泳池内的游动。

## 复现

在已安装的 Python 环境中，从项目根目录运行：

```powershell
python fish_morphologies/generate_fish.py
python fish_morphologies/test_swim.py
```

测试会重建 `swim_results.csv`、`best_gaits.json`、五张轨迹图和五段 GIF。环境原有的 `mujoco`、`numpy`、`matplotlib`、`imageio` 已足够，无新增依赖。
